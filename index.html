01 / Generative AI ERM

AI-powered Safety Text Analytics

Designed a reusable Azure OpenAI GPT-4 pipeline, alongside BERT and topic-modelling methods, to turn large volumes of unstructured safety records into structured, decision-ready insight for industrial clients.

Use cases:

1. Chemicals sector: BERT multi-label classifiers predict consequence types from free-text hazard observations, and the pipeline then infers root causes of injury cases, so the client can flag high-risk observations and target proactive interventions.

2. Consumer health sector: Iterative prompt engineering assessed whether leadership actions or omissions contributed to events across incident, near-miss and audit records from 27 sites, and LDA topic modelling with manual refinement produced a standardised set of gap categories. This reduced manual investigation effort and gave the client cross-region and site-level visibility of recurring gaps to guide targeted process improvements.

3. Industry association: Classified hazards, consequences and work types across 40,000+ incident investigation records within a common taxonomy to surface sector-wide trends, working with safety and human factors specialists.

02 / Predictive ML ERM

Predictive Emissions Monitoring

Where an asset has no continuous emissions analyser, neural-network models can predict its NOx, CO, SO₂ and VOC emissions from operational sensor data. At ERM, I use the company's established pipeline: it augments limited stack-test data using SMOTE, GAN, Gaussian and covariance noise, then trains Keras/TensorFlow models.

I learned the workflow well enough to use it independently, rebuilding client-specific models for gas- and diesel-powered machinery by preparing the data and repeatedly refining the configuration to improve predictions. It demonstrates how quickly I can pick up an established modelling workflow and produce useful results.

GANs RNNs Time series Python

04 / Retrieval Augmented Generation (RAG) Personal

Talk to Wikipedia

Built a local question-answering prototype that retrieves relevant Wikipedia passages using vector search and graph relationships, then generates answers grounded in the retrieved evidence.

The project combines Chroma for semantic passage retrieval, Neo4j for article, topic and chunk relationships, and Ollama for local embeddings and answer generation.

05 / Automation ERM

Document or Process Automation

Every pull request needed a detailed description covering the databases used, files processed, code changes and deployment plan, which took 20–30 minutes to complete. I decided to automate this on my own initiative.

I built a notebook that retrieves commit changes and linked work items from Azure DevOps, then integrated GPT-4 to draft the description using the required template. The process now takes about two minutes and is used by data scientists and software developers on the team.

It is a small tool, but it shows how routine work can be made faster and more consistent.

LLM Azure OpenAI GPT-4 Azure DevOps
